## 4. Spike app

Purpose-built fixtures are generated by `tool/make_fixtures.py` (no third-party
content): EPUB 2 with NCX TOC, EPUB 3 with nested nav TOC, internal link and
footnote, a 12-page PDF alternating Letter portrait / A4 landscape, and a
corrupt EPUB. They are copied into app-private storage on first launch and the
reader opens the local copy.

The reader screen exercises: open/close, `initialLocator` restore, locator
stream with 750 ms debounced save plus save on `paused`, versioned locator
envelope (`lib/spike/locator_envelope.dart`, unit-tested), TOC navigation via
`goByLink`, forward/backward, EPUB font size/theme/scroll and PDF layout/fit
preferences, bookmarks, selection-action highlights reapplied on `ready`,
`searchInPublication`, and a session-generation guard against late events.
Events are logged with a `SPIKE` tag without any publication text.

The spike calls the plugin directly from its reader page. This is acceptable
only in the throwaway spike; the production app must use the adapter (ADR-012).

## 5. Environment issue: Gradle wrapper download

The first `flutter build apk --debug` failed in the Gradle wrapper with
`ConnectException: Operation timed out`, both inside Claude Code and in a
normal terminal, so it is not a sandbox issue.

Cause (local network, not the project): `services.gradle.org` redirects to
`release-assets.githubusercontent.com`, and one of its four IPv4 addresses
(`185.199.109.133`) is unreachable from this network. `curl` falls back to
another address; Java's `HttpURLConnection` does not, so the download fails
whenever that address resolves first.

Workaround used: download the distribution with `curl`, verify it against
the published `gradle-9.3.1-all.zip.sha256`, and place it in the wrapper cache
(`~/.gradle/wrapper/dists/gradle-9.3.1-all/<hash>/`). This is a per-machine
step; it does not change the project. Repeat it if the wrapper version changes
while on this network.

### Emulator could not boot

The only installed system image is API 37.1 with 16 KB pages; neither the
original `Pixel_10` AVD nor the dedicated `reader_spike` AVD ever booted with it.
The guest stalled with near-zero CPU both when started from Claude Code (which
also logged `hvf is not enabled`) and from a normal terminal. Validation moved
to a physical phone. If an emulator is needed later, try a standard 4 KB-page
image such as `system-images;android-36;google_apis;arm64-v8a`.

## 7. Findings

1. The plugin requires JDK 18+ for the Android build (its module sets
   `JavaVersion.VERSION_18`); the README does not say so.
2. Flutter 3.47.9's template AGP (9.1.0) is below the plugin's 9.1.1 minimum.
3. `FlutterReadium` is a singleton with one global open publication, matching
   the single-session policy (spec §5.3).
4. `setPDFPreferences` replaces all PDF preferences on each call; the adapter
   must always send the full set.
5. EPUB `fontSize` is a ratio clamped to 0.1–5.0, not a point size.
6. Android opens PDFs paginated by default.
7. First Android build took ~16 minutes; incremental builds ~8 s.
8. Debug APK is 184 MB; the plugin bundles TTS/audio/Media3 unconditionally.
   Measure the release build.
9. EPUB locators include `cssSelector`, `tocHref`, `currentPage`/`totalPages`,
   `progression`, `position`, `totalProgression`; no text context. Selection
   locators include `text.before/highlight/after`. In the generated fixtures,
   `position`/`totalProgression` only change per chapter, probably because
   the repetitive chapters compress below 1 KB (unconfirmed; recheck with a
   real book).
10. **No locator event after an EPUB preference change** (font 100 → 160%
    reflowed the page but no new locator arrived). The adapter must not assume
    the saved position stays current after reflow; consider re-reading the
    position after applying preferences.
11. **EPUB highlights render correctly; the earlier failure was a fixture
    artefact.** The first fixture repeated identical paragraphs in two sections
    of a chapter. Selection locators carry only text context
    (`text.before/highlight/after`, ~190 characters each side) with no
    `cssSelector` or DOM range, so Readium anchored the decoration to the
    *first* matching passage, two pages earlier, which made it look missing.
    Confirmed by inspecting the WebView DOM over DevTools (the
    `r2-highlight` element sat exactly on the earlier occurrence) and by
    seeing it on that page. With unique paragraph text, the highlight renders
    on the selected word and is reapplied after a force-stop. **Residual
    risk:** in a real book, a passage repeated with identical surrounding text
    (refrains, boilerplate) would highlight the first occurrence. Rare;
    document it, no MVP mitigation planned.
12. `ReaderDecorationStyle.toJson()` writes `tint` as a CSS string but
    `fromJson()` casts it to `int`, so plugin decoration JSON does not round-
    trip. Store highlights in the app's own schema (as the database spec
    already intends) and rebuild `ReaderDecoration` at apply time.
13. Selection is not cleared after a custom selection action; the app must
    clear or ignore it.
14. **PDF search fails on Android** with `SearchError`, despite the README
    listing content search for Android. Hide PDF search unless fixed.
15. Non-linear spine items (`linear="no"`, e.g. footnote documents) are
    excluded from `readingOrder` and from search.
16. **Privacy:** the plugin's `LogLevel.debug` writes publication text
    (selected text and its context) to logcat. Production must never enable
    plugin debug logging.
17. `ReadiumException.message` is technical ("An error occurred while
    attempting to decode the content."); map codes to app-owned user messages.

## 8. Decision

**Android: proceed with `flutter_readium` 0.9.0.** Core reading, navigation,
TOC, preferences, progress restore (including after process death),
bookmarks, EPUB highlights (create and reapply), EPUB search, error handling
and lifecycle all work on a physical device.

Constraints to carry into the reader design:

- Hide PDF search on Android (finding 14); it is not an MVP requirement.
- Store highlights in the app schema, not plugin JSON (finding 12).
- Re-read the position after applying EPUB preferences (finding 10).
- Clear selection after the highlight action (finding 13).
- Never enable plugin debug logging (finding 16).

Still open: airplane-mode run, footnote popup, large-PDF fixture, release APK
size. iOS validation is deferred, so Milestone 0 cannot be fully signed off
under `IMPLEMENTATION_PLAN.md` §4 until it resumes.
